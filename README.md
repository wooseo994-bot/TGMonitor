# TGMonitor · 远程协作台

Telegram 工作群抽查与主管复核。

## 本地演示

需要 Node.js 24 或更新版本，无需安装第三方依赖。

```sh
DEMO=1 npm start
```

打开 http://127.0.0.1:3000/?demo 。演示账号是 `admin@example.com`，密码是 `demo-password-123`。
在「抽查批次」发起模拟抽查，展开名单后模拟目标员工点击。演示模式使用内存数据库和模拟 Telegram 请求。

## 接入测试群

1. 设置 `APP_KEY`（用 `openssl rand -hex 32` 生成并安全备份）、`ADMIN_EMAIL`、至少 12 位的 `ADMIN_PASSWORD` 和面向 Telegram 的 HTTPS `PUBLIC_URL`。使用 HTTPS 反向代理将请求转给应用。应用默认监听 `127.0.0.1:3000`。
2. 运行 `npm start`。SQLite 默认位于 `data/app.sqlite`；部署时挂载持久卷并限制访问。建议单进程运行。
3. 将机器人设为测试群管理员，在后台填写 Bot Token 与群 ID。验证后，在群里用管理员账号点击测试按钮，再启用自动抽查。
4. 导入已有成员的 Telegram ID 与姓名。确认班次规则后试发一批，核对目标、确认回执和报表。

凭据只通过部署环境或后台输入。请勿把密钥、员工名单或数据库提交到 Git。

## 当前实现范围

单实例单群、工作日班次、随机轮换、群内确认、入退群事件、名单维护、待复核记录、日/周统计和 CSV、管理员和主管角色、手动发放邀请或密码重置链接。暂缺多群授权、邮件验证/投递、自动名单对账、复查权重、完整采集故障检测、数据保留自动清理及可选 AI 摘要。真实 Telegram 群和 HTTPS 部署需联调。
